# Phase 0 (Foundations) — Plan Index

> **For agentic workers:** Phase 0 is split into five sub-plans (writing-plans scope check: one plan per subsystem).
> Execute in the order below. Each sub-plan produces working, tested software on its own and lists the interfaces it
> consumes from earlier sub-plans and produces for later ones. REQUIRED SUB-SKILL per sub-plan:
> superpowers:subagent-driven-development (recommended) or superpowers:executing-plans.

**Goal:** P0 exit criteria of `docs/plan/ROADMAP.md` §P0 — install Tradeloom on Linux, log in to Kite daily, see live
charts, ticker, watchlists, read-only holdings/positions/order book, settings, logs, backup/restore. No order placement.

**Specs (read before any sub-plan):** `docs/requirements/REQUIREMENTS.md` v2.2 (the FRs listed per sub-plan),
`docs/architecture/ARCHITECTURE.md` (§2 layout & rules, §3 runtime, §4 data, §5 Kite, §8 frontend, §9 security,
§10 CI, §11 testing, §12 P0 breakdown), `docs/plan/ROADMAP.md` §P0 (exit criteria, spikes) and §6 (gate G-0).

## Plan layout (context budget)

Each sub-plan is a directory, so no agent ever loads a whole plan:

- `MANIFEST.md` — header, Global Constraints, Review Focus, File Structure, Consumes/Produces, plus a task table
  (file, approximate size, earlier tasks it consumes). The coordinator holds only manifests.
- `tasks/NN-<slug>.md` — one task, verbatim. An implementer reads its plan's `MANIFEST.md` plus its one task file
  (largest manifest ≈ 16k tokens, largest task ≈ 20k).
- `APPENDIX.md` — acceptance-criteria coverage and self-review (for reviewers, not implementers).

`python3 -I plan_split.py join <dir>` reassembles a sub-plan byte-exactly; `check_p0_interfaces.py` reads the plans that
way. Edit the task files directly; re-run the checker after any interface change.

## Shared contract (names every sub-plan must use — from ARCHITECTURE.md §2.2)

Package paths: `tradeloom/internal/{app,service,bus,kite,kite/ratelimit,kite/ticker,kite/orderwrite,kite/mock,calendar,
clock,candles,candles/backfill,candles/builder,instruments,store,secrets,settings,logging,orders,archtest}`; frontend
under `frontend/src/`. Key types: `bus.Bus`/`bus.Topic[T]`; `clock.Clock`; `calendar.Service`; `kite.ReadClient`,
`kite.Session`, `kite.Err`; `ratelimit.Limiter`/`Class`/`Priority`; `ticker.Manager`/`Consumer`/`Mode`;
`candles.Store`/`Candle`/`Interval`/`Coverage`/`Builder`/`Backfill`; `instruments.Master`/`Instrument`/`Search`;
`store.DB`/`Migrator`; `secrets.Store`/`Key`; `settings.Settings`/`Key[T]`; `logging.Redactor`; `service.Service`.
Each sub-plan's "Interfaces → Produces" blocks give the exact signatures; later sub-plans copy them verbatim. P0-1 and P0-2
Produces are authoritative for Go (their code was executed); P0-3 is authoritative for Wails bindings and events; P0-4
Tasks 1–6/12/19 are authoritative for the shell components P0-5 consumes. Version pins: modernc.org/sqlite v1.59.0 and
golang.org/x/crypto v0.55.0 (the newer v1.60.1 / v0.58.0 require Go 1.26).

Build tags for every P0 build and test run: `-tags webkit2_41,noorders` (G-0). Go 1.25, `GOWORK=off` in CI.
Rules 1–8 of ARCHITECTURE §2.4 are enforced by `internal/archtest` from P0-1 onward.
